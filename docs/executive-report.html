Summary

Executive summary

SalesIQ is not a CRM add-on. It's the layer CRM never built: a live, explainable decision engine that runs the actual moment of choice — in front of the customer, on a screen they're looking at, with reasons a buying committee could defend.

The platform proves its own "industry-agnostic" thesis in code, not slides: the identical engine and UI already power real estate (two packs — one hand-curated, one at 500-listing scale), automotive, private aviation, and yacht charter. A new vertical is configuration, authored through a no-code Visual Builder — not an engineering rebuild.

North Star: every recommendation shown to a customer must be explainable from real, inspectable facts — enforced by a deterministic scoring/narration engine, with Claude layered on top only as an optional writing upgrade that never gets to invent a reason.
Problem

Enterprise buying is improvised and invisible

A six-figure decision — a property, a fleet vehicle, a private aircraft — is still sold the way it was twenty years ago: a rep talking, a customer nodding, and a CRM that only learns about the deal after the fact.

GapToday's reality
Improvised pitchEvery rep builds their own mental model of fit — inconsistent, unmeasurable, uncoachable
Invisible reasoning"Trust me" is not a reason a buying committee can defend, or a manager can audit
Activity, not judgmentCRM logs that a call happened, never why option A beat option B
One-vertical toolsSales-enablement and CPQ tools are typically built for a single industry's data shape

CRM, sales-enablement libraries, and configure-price-quote tools each own a slice — none of them own the live moment of decision. That gap is the category SalesIQ was built for.

Solution

One core loop: configure → question → score → explain → present → propose

A rep's questions feed a live scoring engine; the engine ranks every inventory item and generates a plain-language explanation from its own real rule breakdown — never a canned script. The customer sees this unfold live, on their own screen.

COMPANION  →  DECISION ENGINE (rules · explanations · AI upgrade)  →  DISPLAY  →  PROPOSAL
The engine doesn't know or care what it's selling — the pack supplies the questions, inventory, and rules.

What this changes for the business

  • Consistency: every rep runs the same explainable logic, not their own improvisation.
  • Coachability: the AI Sales Twin and Sales Copilot read the same real session data a manager could review.
  • Defensibility: a recommendation traces to real facts a buying committee can actually interrogate.
  • Portability: the exact same product runs a new vertical as configuration, not a rebuild.

Module · Shipped

Buyer Intelligence — a persistent Buyer Brain

Until this phase, the platform had no persistent customer identity at all — every Companion session, brochure capture, and kiosk lead created a fully disconnected row. Buyer Intelligence closes that gap: a buyer is auto-matched by normalized email/phone into one profile that survives across every session and capture surface, private to the sales team and never reachable from the customer-facing Display, Brochure, or Shared Experience.

CapabilityReal detail
Data provenanceEvery requirement/financial fact is tagged explicit, inferred, or observed — never presented as a bare, unsourced fact
Feeds the real engineA buyer's priorities weight the existing scoring engine's own rules directly — verified to measurably shift the ranking, not a parallel scoring system
Natural-language captureFree-text "describe the customer," with a mandatory Confirm/Edit/Reject before anything is trusted as fact
Behavioral trackingViews, saves, and proposals log automatically once a buyer is identified — never retroactively
Intent & readinessA deterministic, evidence-backed classification — Low/Medium/High/Very High intent, an 8-stage purchase-readiness journey with a real confidence percentage
Access controlThe platform's first row-level boundary: a Salesperson sees only their own branch/assigned buyers
Buyer TimelineEvery requirement change, activity event, conversation capture and objection merged into one chronological feed — including item-relationship states never rendered anywhere before
SegmentationA segment is a saved filter compiled into a live query on every read — its buyer count is never a stale snapshot
SimilarityA deterministic, weighted shared-attribute match — every result names the real attributes it shares, never a bare score
Configurable Next Best ActionTenant-authored rules evaluate first; the original Wave 1 hint is the guaranteed fallback, verified byte-identical for an untouched tenant
Management aggregate viewThe platform's first genuine server-side groupBy/count rollup — intent/readiness distribution, top objections, segment summaries, a needs-attention list — scoped exactly like the buyer list
Status: Both waves (11 PRs total) are complete and verified end-to-end, including a dedicated privacy-boundary re-check against every public route and against the newly-added segmentation/aggregate routes.

Module · Shipped

LUMMA — the Sales Companion becomes a guided experience

The Companion stopped being a tool the salesperson operates and became a script the salesperson follows: a real login (dashboard-provisioned accounts only, no self-signup), a privacy-masked "meet the customer" step, then an 8-step discovery journey that narrows toward the real recommendation live as it's answered — before landing, unchanged, in the existing Companion workspace.

CapabilityReal detail
8-step discoveryHousehold, Location & Commute, Location Preferences, Property Type, Lifestyle, Home Features, Financial, Timing — replacing a 5-question minimal wizard
Real commute scoringA geocoded workplace and a real haversine distance to each listing bias the actual scoring engine, not a second one
Real amenity scoringOnly nearby-preference kinds with a genuine OpenStreetMap counterpart move the score; the rest are still captured, honestly, as data
Priority rankingA top-3 "what matters most" ranking feeds the same importance-weighting mechanism Buyer Intelligence already had
Live buyer profile panelTap-to-edit view of everything captured so far, jumping straight back into the relevant step
Confirmation screenA "here's what we heard" recap between the wizard and the workspace, with the same real match count the wizard already computed
Customer display syncSection checkmarks and a narrowing match count on the big screen, sourced only from the pack, answers and scores — never contact details
Natural-language pre-fill"Describe the customer" free text maps onto real wizard answers to confirm, reusing the existing Confirm/Edit/Reject discipline
Use existing profileThe platform's first BuyerProfile→answers reverse mapping, for a returning buyer
Geocode fallbackTry again, enter manually from the pack's own real districts, or skip — never a dead end, never an invented location
Status: Both rounds (4 PRs total) are complete and verified live via Playwright against a running server, including a two-tab pass confirming the customer display stays in sync with discovery.

Foundation

A real backend, not a demo login screen

  • Multi-tenant Postgres, real auth: bcrypt-hashed passwords, signed sessions verified server-side against a real Session table; suspension actually locks a user out immediately.
  • Real RBAC: Owner / Admin / Manager / Designer / Salesperson / Viewer, enforced server-side on every route.
  • Proven isolation: cross-tenant data isolation verified by a dedicated automated test, not assumed.
  • Real CI: typecheck/lint/build/e2e against an isolated Postgres database on every push.
