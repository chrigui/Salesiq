Strategy

Executive summary

Enterprise buying is improvised, invisible, and CRM tells you what happened rather than what to do next. SalesIQ is the category built to fix that: a Decision Intelligence Platform where a live scoring engine — never a black box — turns a customer's answers into a ranked, explainable recommendation in real time, on a screen the customer is actually looking at. The same engine, the same UI, and the same admin tooling already power five completely different industries from one shared codebase, proving the "industry-agnostic" thesis isn't a slide — it's the architecture.

North Star: every recommendation a customer sees on screen must be explainable in plain language from real facts — no invented statistics, no "AI vibes." That discipline is enforced in code (the scoring engine and the narrator are deterministic; Claude is an optional writing upgrade layered on top of facts it doesn't get to invent) — not just claimed in a deck.

SalesIQ is built on Next.js 15 / React 19, backed by a real multi-tenant Postgres schema (Prisma), with genuine role-based permissions and audit logging rather than a demo-only login screen. Everything described in this report as "live" is running code in this repository today; everything described as roadmap is explicitly labeled as such, using the same shipped/roadmap vocabulary the product's own internal documentation already uses (live-dot / To activate / Next up / Blueprint).

Problem

Enterprise buying is improvised and invisible

A six-figure purchase decision — a property, a fleet vehicle, a private aircraft, a yacht charter — still gets sold the way it did twenty years ago: a rep talking, a customer nodding, and a CRM that only ever learns about the deal after the fact.

The pitch is improvised

Every rep builds their own mental model of "what this customer needs" — inconsistent, unmeasurable, and impossible to coach systematically.

The reasoning is invisible

"Trust me, this is the right fit" is not a reason a buying committee can defend internally — and it's not something a sales leader can audit or improve.

The system remembers activity, not judgment

A CRM logs that a call happened. It has no record of why option A beat option B, so the next rep — or the next AI feature bolted onto the CRM — starts from zero.

CRM, sales-enablement content libraries, and configure-price-quote tools each own a slice of this problem, but none of them own the actual moment of decision — the live comparison, in front of the customer, that ends in a recommendation someone can defend. That gap is the category SalesIQ was built for.

Product

How it works

One core loop, running identically underneath every industry pack: configure → question → score → explain → present → propose.

The rep's phone drives the questions; the same live scoring runs the ranked recommendation on the customer-facing screen with real, inspectable reasons — never a canned script.

Every industry pack — real estate, automotive, aviation, yacht charter, or a brand-new one authored with zero code through the Visual Builder — plugs into this exact loop. The engine doesn't know or care what it's selling.

Architecture

Five surfaces, one decision engine

Customer Experience Display

The big-screen surface a customer actually looks at — Interactive Lifestyle Map (MapLibre 3D terrain, day/night, animated walking routes), ranked recommendations, live proposal presentation.

Sales Companion

The rep's phone/tablet — question flow, AI Sales Twin, Buying Committee Intelligence, Sales Copilot, proposal generation, natural-language customer search.

Company Dashboard

Leads/CRM, Business Impact Dashboard, Deal Probability Radar, ROI Calculator, Brochures & Deal Rooms, Visual Builder, Knowledge Base, AI settings.

Platform Administration

Multi-tenant org management, users & branches, real role-based permissions, audit trail, security & compliance, subscription/billing UI.

AI Decision Engine & Public API

The scoring/explanation engine itself, exposed as a public REST API (/api/public/v1) — the same engine every surface above calls internally.

Real-time state sync ties Display and Companion together live: QR-code pairing, same-device broadcast bus, cross-device MQTT/WebSocket transport, AES-GCM encrypted room keys, and an offline queue that auto-flushes on reconnect.

Industry-agnostic by design

One engine, five verticals, zero code changes

An "industry pack" is a single config object — branding, questions, inventory, scoring rules. Swap the pack and the entire product becomes a different business. Nothing about the engine or UI is real-estate-specific, automotive-specific, or aviation-specific.

AI-native, not AI-bolted-on

Tracks every stakeholder, role, and influence level in a deal — built for the multi-signoff reality of enterprise purchases.

In progressModule

Deal Room & Template Engine

Generalizes the Brochure engine into a reusable, versioned, industry-agnostic Deal Room: a template is built and versioned independently of any specific deal, then instantiated into a live room frozen to the exact template version it was built from — so a negotiation never silently reflows if the master template changes mid-deal.

PR 1 — shipped

Data model and schema: DealRoomTemplate, versioned snapshots, DealRoom instances, tasks, chat, approval steps, signature requests — plus a new Designer role and three permission capabilities.

PRs 2–10 — planned

Template Builder UI (real drag-and-drop), the widget library, the rendering engine, theming, versioning/rollback, full permission enforcement, analytics, an AI layout assistant, and production hardening.

What's deliberately not faked

Signature and Chat ship with real data models and UI, honestly marked "not connected" until a real e-signature vendor and realtime provider are chosen — no fabricated "connected" state.

Foundation

A real backend, not a demo login screen

Multi-tenant Postgres, real auth

bcrypt-hashed passwords, signed session cookies verified server-side against a real Session table (a suspended user is actually locked out, immediately) — cross-tenant data isolation proven by a dedicated automated test, not just assumed.

Real role-based permissions

Owner / Admin / Manager / Designer / Salesperson / Viewer, each capability enforced server-side on every route — the same pattern extended cleanly for Brochures and now Deal Rooms, not a one-off.

CI runs the full typecheck/lint/build/e2e suite against a real, isolated Postgres database on every push. GDPR export and PII redaction, tenant audit trails, and a demo-safety kit round out the compliance surface.

Roadmap

What's next, honestly labeled

SalesIQ's own internal documentation already distinguishes three tiers of "not yet" — reused verbatim here rather than inventing a new vocabulary.

To activate

Code already exists — a config/deploy step is what's left. Setting a production Claude API key; confirming the Vercel auto-deploy pipeline; provisioning production Postgres.

Next up

Real build work remaining. Migrating the last localStorage-backed settings stores to Postgres; live payment processing behind the real Billing Center UI; federated SSO sign-in; five more industry verticals (medical, solar, insurance, education, hospitality).

Blueprint

Designed, not wired. Native iOS/Android apps (the installable PWA ships today); AR/VR/IoT/digital-twin; custom scoring math beyond the built-in rule types; drag-on-map POI placement.
