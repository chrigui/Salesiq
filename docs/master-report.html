Strategy

Executive summary

Enterprise buying is improvised, invisible, and CRM tells you what happened rather than what to do next. SalesIQ is the category built to fix that: a Decision Intelligence Platform where a live scoring engine — never a black box — turns a customer's answers into a ranked, explainable recommendation in real time, on a screen the customer is actually looking at. The same engine, the same UI, and the same admin tooling already power six industry packs across four verticals from one shared codebase, proving the "industry-agnostic" thesis isn't a slide — it's the architecture.

North Star: every recommendation a customer sees on screen must be explainable in plain language from real facts — no invented statistics, no "AI vibes." That discipline is enforced in code (the scoring engine and the narrator are deterministic; Claude is an optional writing upgrade layered on top of facts it doesn't get to invent) — not just claimed in a deck.

SalesIQ is built on Next.js 15 / React 19, backed by a real multi-tenant Postgres schema (Prisma), with genuine role-based permissions and audit logging rather than a demo-only login screen. Everything described in this report as "live" is running code in this repository today; everything described as roadmap is explicitly labeled as such, using the same shipped/roadmap vocabulary the product's own internal documentation already uses (live-dot / To activate / Next up / Blueprint).

Problem

Enterprise buying is improvised and invisible

A six-figure purchase decision — a property, a fleet vehicle, a private aircraft, a yacht charter — still gets sold the way it did twenty years ago: a rep talking, a customer nodding, and a CRM that only ever learns about the deal after the fact.

The pitch is improvised

Every rep builds their own mental model of "what this customer needs" — inconsistent, unmeasurable, and impossible to coach systematically.

The reasoning is invisible

"Trust me, this is the right fit" is not a reason a buying committee can defend internally — and it's not something a sales leader can audit or improve.

The system remembers activity, not judgment

A CRM logs that a call happened. It has no record of why option A beat option B, so the next rep — or the next AI feature bolted onto the CRM — starts from zero.

CRM, sales-enablement content libraries, and configure-price-quote tools each own a slice of this problem, but none of them own the actual moment of decision — the live comparison, in front of the customer, that ends in a recommendation someone can defend. That gap is the category SalesIQ was built for.

Product

How it works

One core loop, running identically underneath every industry pack: configure → question → score → explain → present → propose.

The rep's phone drives the questions; the same live scoring runs the ranked recommendation on the customer-facing screen with real, inspectable reasons — never a canned script.

Every industry pack — real estate, automotive, aviation, yacht charter, or a brand-new one authored with zero code through the Visual Builder — plugs into this exact loop. The engine doesn't know or care what it's selling.

ShippedModule

Buyer Intelligence — a persistent Buyer Brain

Until this phase the platform had no persistent customer identity at all: every Companion session, brochure capture, and kiosk lead created a fully disconnected row, and nothing survived a session reset beyond a final Lead snapshot. Buyer Intelligence closes that gap with a private, per-buyer profile — auto-matched by normalized email/phone, feeding the one real recommendation engine, and strictly walled off from every customer-facing surface.

Explicit / inferred / observed

Every requirement and financial fact carries its own provenance, confidence, and evidence — never a bare, unsourced fact.

Feeds the real engine, not a parallel one

A buyer's stated priorities weight the existing scoring engine's own rules directly — verified with a real ranking-flip test, not just noted on a card.

Confirm / edit / reject, always

Natural-language "describe the customer" capture never auto-applies — every extracted field requires an explicit human decision before it's trusted as fact.

Behavioral & relationship tracking

Views, saves, and proposals log automatically once a buyer is identified; an append-only per-item state log means a listing's story over time is never overwritten.

Rejected options exclude in real time

Rule out an item with a reason and it stops recommending for that buyer immediately — a live re-scoring test, not a static flag.

Evidence-based Intent & Readiness

Low/Medium/High/Very High intent and an 8-stage purchase-readiness journey with a real confidence percentage — always with the reasons attached, never a bare score.

Objection tracking, repeat-aware

Every objection raised through the existing Objection Handler persists, with confidence rising when the same objection repeats.

Row-level access scoping

The platform's first access boundary narrower than tenant-wide: a Salesperson sees only their own branch or assigned buyers; Manager and above see the full tenant.

Verified privacy boundary

Confirmed against real public routes — a buyer profile carrying rich objection/intent data never appears on the Customer Display, Brochure, or Shared Experience.

Unified Buyer Timeline

Every requirement change, activity event, conversation capture, and objection merged into one chronological feed — including item-relationship states never rendered anywhere before.

Buyer Segmentation

A segment is a saved, declarative filter compiled into a live query on every read — its buyer count is never a stale snapshot.

Buyer Similarity

A deterministic, weighted shared-attribute match — every result names the real attributes it shares, never a bare score.

Configurable Next Best Action

Tenant-authored rules evaluate first; the original Wave 1 hint is the guaranteed fallback, verified byte-identical for an untouched tenant.

Management aggregate view

The platform's first genuine server-side groupBy/count rollup — intent/readiness distribution, top objections, a needs-attention list — scoped exactly like the buyer list itself.

Scope: both Wave 1 (6 PRs) and Wave 2 (5 PRs) are complete and verified end-to-end, including a privacy-boundary re-check against the newly-added segmentation/aggregate routes.

LUMMA — the Sales Companion becomes a guided experience

The Companion stopped being a tool the salesperson operates and became a script the salesperson follows: a real login gate (dashboard-provisioned accounts only, no self-signup), a privacy-masked "meet the customer" step, then an 8-step discovery journey that narrows toward the real recommendation live as it's answered — before landing, unchanged, in the existing Companion workspace. Everything reuses what already existed: Buyer Intelligence, the one real scoring engine, and the Customer Display.

Real login, no self-signup

The exact same session-cookie pattern /dashboard already uses — accounts are provisioned from the dashboard, never self-registered.

8-step discovery journey

Household, Location & Commute, Location Preferences, Property Type, Lifestyle, Home Features, Financial, Timing — replacing a 5-question minimal wizard.

Real commute-distance scoring

A geocoded workplace and the same haversine distance math used everywhere else bias the actual scoring engine's own weights — never a second, parallel system.

Real nearby-amenity scoring

Only preference kinds with a genuine OpenStreetMap counterpart on a listing move the score; the rest are still captured, honestly, as structured data.

Top-3 priority ranking

Feeds the same importance-weighting mechanism Buyer Intelligence already had, mapped to a real question wherever one exists.

Live, tap-to-edit buyer profile panel

Everything captured so far during discovery, in one view, jumping straight back to the relevant step to correct it.

"Here's what we heard" confirmation

A compact recap between the wizard's last step and the workspace, with the same real match count the wizard already computed — no second number to reconcile.

Customer display discovery checklist

Section checkmarks and a narrative match-count on the big screen as discovery narrows, sourced only from the pack, answers and scores — never contact details.

Natural-language pre-fill

"Describe the customer" free text maps onto real wizard answers to confirm, reusing the existing Confirm/Edit/Reject discipline rather than a new capture path.

Use existing profile

The platform's first BuyerProfile→answers reverse mapping — a returning buyer's saved requirements pre-fill the wizard instead of re-asking from scratch.

Geocode fallback, never a dead end

Try again, enter the location manually from the pack's own real districts, or skip — never an invented place, never a stuck screen.

New-meeting state reset

Starting a new meeting now clears the previous customer's discovery answers while keeping the salesperson's chosen industry pack — a real gap found and fixed along the way.

Two rounds, 4 PRs total, all shipped and verified live via Playwright against a running Postgres-backed server — including a two-tab pass confirming the customer display checklist stays in sync with discovery in real time.

THE LUMMA RECAP

Every prior recap was ephemeral — tied to a live sync room, gone the moment the session ended. THE LUMMA RECAP replaces it with a real, durable database record and a short public link at /r/[code] the customer can reopen for days afterward, on any device, with no login — reusing the exact same scoring engine, Buyer Intelligence and privacy discipline as every other surface, never a parallel system.

Salesperson review

Per-section Edit/Hide control before anything is ever sent, plus a private-notes field structurally unreachable from any customer-facing code path — not merely unrendered, verified by a dedicated safety test that probes the public route for it directly.

Thank-you story templates

Thank you / Follow-up / Personal note starting drafts, always editable before the recap is created.

Live price & availability

Property ids and the salesperson's authored text freeze at creation; price and availability are always re-resolved live against the real inventory pack.

"Since your last visit"

An honest diff against the customer's own last real view — a "price updated" badge (old struck through, new shown), or a "no longer available" block with real closest alternatives, never a fabricated substitute.

Comparison Continuity

"You compared…" preserved exactly as it stood at the end of the meeting, with the same real difference lines — never re-run or reset on reopen.

Customer favoriting

A pure engagement signal derived from an append-only event log — it never mutates the salesperson's official shortlist.

WhatsApp / Email sharing

Real, editable wa.me/mailto: deep-links prefilled with the real recap URL — no backend messaging vendor added.

Engagement signals & activity feed

Every real interaction — a view, an expanded property, a viewed payment plan, a favorite — feeds a privacy-conscious OBSERVED/INFERRED engagement level and a live activity feed on the buyer's own profile.

Property status-sync banners

Surfaces price/availability drift on the salesperson's own buyer profile even if the customer never reopens the link.

Security-hardened public surface

Archived, expired and unknown codes are indistinguishable to a stranger probing them — same 404, same body — and every field reachable from the public route routes through an explicit allowlist seam.

20 PRs plus a comprehensive acceptance test, all verified live against a running server with real API round-trips — including a run that independently confirmed, via a clean pre-change baseline, that an unrelated pre-existing test-suite flake was not caused by this work.
